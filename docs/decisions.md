# Design decisions

- **2026-10-09 — Single-owner worker:** One thread owns clipboard access and the SQLite connection. UI commands travel through a bounded channel (an in-process queue with room for 64 commands); Windows messages wake the worker. This avoids concurrent clipboard operations and UI stalls without adding an async runtime or several locking threads.
- **2026-10-09 — SQLite transactions:** A transaction commits a group of database changes together or rolls them back together. Bundled SQLite persists exact text, deduplicates with a binary text comparison, and prunes to 200 entries in the same transaction; a JSON file would require rewriting the entire history and implementing safe replacement ourselves.
- **2026-10-09 — Stable identity and recency:** Each entry has a permanent numeric ID, a UTC millisecond timestamp, and a separate increasing recency number. Selection follows the ID; ordering follows recency, so identical timestamps or a clock correction cannot reorder entries incorrectly. UI IDs are strings because Slint integers are smaller than SQLite IDs.
- **2026-10-09 — On-demand detail:** List queries retrieve only IDs, timestamps, and the first 100 Unicode characters for previews. Full text is fetched for the selected entry. This avoids loading up to 200 MiB into a list model; if history grows substantially, indexed hashes for deduplication and paged queries would be worth evaluating.
- **2026-10-09 — Native notifications:** A Windows message-only window subscribes to clipboard changes instead of a polling timer. Sequence numbers identify repeated notifications, while sequence plus exact text suppresses the app's Copy operation without suppressing a later external copy of the same text. A clipboard is a single current value: several very rapid replacements can overwrite intermediate values before a listener reads them.
- **2026-10-09 — Bounded failure handling:** Busy clipboard operations retry after 25, 50, and 100 ms; SQLite waits at most 250 ms for locks. Errors reach the status line, and unreadable databases stay in place. Unbounded retries would leave shutdown and user commands waiting indefinitely; separate database recovery remains a later task.
- **2026-10-09 — Fixed light palette:** Standard widgets use a light palette to match the starter's light background. Following the system palette alone produced unreadable text on a Windows dark-theme machine; a complete theme-aware design can replace this when theming is added.
- **2026-10-09 — Project ignore rules:** Ignore the clipboard database by its actual filename, including SQLite sidecars and named backups, rather than ignoring every database file. This keeps local clipboard content out of normal Git additions while allowing future intentional database fixtures; retain Cargo.lock and shared VS Code configuration for reproducible development.
